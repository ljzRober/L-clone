# 设计理念

> 回到 [README](../README.md) | 架构图见 [ARCHITECTURE.md](ARCHITECTURE.md)

## 横向分层(记忆等级 × 时间)

```
L0 流水层   sessions    每次工作一句话摘要 (自动记录, 零打扰)
L1 决策层   memories    决策 / 记录 (大脑的核心记忆)
L2 规划层   specs_index 项目内 spec 文件的索引 (权威内容在仓库)
```

## 竖向分层(项目维度 + 模块维度)

- 每个项目一个命名空间 (`project_id`);`NULL` = 个人区(全局层, 生命周期无限)
- 项目内再分**模块**(次级竖向划分): 仅决策挂模块, 记录无模块(落在项目层)。
  模块名由 LLM 分类、代码维护词表(归一化/复用/防泛名, 如 core/misc 等泛名挂项目层)
- **项目内**:spec/决策/代码留在仓库, 采用业界约定 (OpenSpec / ADR 等,
  格式可换——大脑按路径模式启发式识别, 不绑定任何工具)
- **大脑内**:只管理大方向 (charter)、决策记忆、记录、跨项目召回

## 记忆写入策略(B + C)

```
C 主动触发 (lclone remember "…")   -> 你说算
B 自动捕获 (lclone capture "…")    -> LLM 提炼决策/记录
                                      决策(decision) -> pending 草稿区 -> 你 review 确认
                                      记录(note)     -> active 直接生效 (免确认)
```

**决策强确认(统一规则)**:无论 B 还是 C, **decision 一律进 pending 草稿, 你盖章后才生效**。
`remember` 加 `--confirmed` 表示当场已确认、直接生效;`--level note` 恒直接生效。

每条记忆带来源引用 (`source_ref`), 可追溯。

**准入过滤(代码强制, 不依赖模型意图)**:
- 排除「做了什么」(修复/重构/改接口/修 bug) → 归 git 与 spec, 不进记忆;
- 决策自筛: 只提炼「定下选择/规则」, 且用户提议被助手确认/落地才算 decision,
  随口一提不提炼;标注 decision 但无决策信号自动降级 note;
- 琐碎过短(不足 4 字)的记录丢弃。

**note 逐轮追加与滚动压缩**:自动捕获按 `session_key`(外部会话 id)聚合,
同一会话只建一条 note, 每轮追加原文;超长时整条摘要一次, 保持有界。

**分类加载**:读取时按「项目 → 模块」分组注入, 决策/记录分开呈现, 减少噪声。

**为什么只对决策加确认制**:决策是权威结论, AI 自动总结可能幻觉、过度概括,
必须"AI 写草稿、你盖章"; 记录只是过程性事实/TODO/观察, 记错了也无害,
免确认直接进库, 事后可删。

## 两个回路

```
回顾环: 新会话 -> 召回相关记忆 + 项目上下文 -> 注入问答
规范环: 新提议 -> 调出项目 spec/边界 -> 逐条对照 -> ✅/⚠️/❌ 检查报告
```

## 生命周期: 读取时决定, 不落状态字段

记忆没有"归档/未归档"之分, 只有"加载/不加载"这一读取时决策:

- **全局层** (project_id=NULL, 个人区) 的记忆生命周期无限, 永远加载。
- **项目记忆**的生命周期与所挂靠的竖向切分绑定: 项目"活着"就加载。
- `proj rm` 是墓碑式移除: 不删行、不加 status 字段, 只在 `project_removals`
  登记移除事件。读取时 (recall/ask/proj list) 据此跳过已移除项目的记忆;
  数据保留, `proj restore` 可复活。真正删除由用户经 `suggest` 提示后手动决定。
- **上升/下降** (promote/demote) 只是改 `project_id`, 不产生任何生命周期状态:
  - `promote`: 项目记忆 → 全局层 (多个项目要共读时)
  - `demote --project X`: 挂到指定项目 (不需要全局保持时; 也用于项目间横搬)

## 记忆链接: 竖向切分之外的第二张网

竖向切分 (全局/项目/模块) 是默认归属; 当记忆之间需要"跨层引用"时,
不必复制也不必搬动, 在内容里写 `[[m:12]]` 即指向记忆 #12:

- 链接写入时解析存入 `memory_links` 表, 跟随 `ON DELETE CASCADE` 自动清理。
- 召回命中 A 时, 自动顺藤把 A 链接指向的记忆一起带出 (一层、限量,
  `recall --no-follow` 可关闭), 不受竖向切分限制——这就是"共享上下文"的落点。
- `recall_log` 记录每次召回, 支撑 `suggest` 的"长期未用"删除提示。

## 删除提示 (suggest) 与整理合并 (organize)

删除始终由用户决定; 算法只负责提示候选: 疑似重复 (向量相似度) /
长期未确认草稿 / 长期未召回 (基于召回日志) / 已移除项目的记忆。

`organize` 反向做「合并」: LLM 把语义相近、说的是同一件事的记忆合成一条综合描述,
硬约束为**同项目 + 同等级 + 同模块**才可合并, 跨区域由代码校验拒绝。

## 与现有生态的关系

- 存储设计借鉴 **GBrain** 思想(pages/时间线 → 我们的 sessions/版本化记忆)
- 竖向分层兼容 **OpenSpec**(`.specs/`)与 **ADR**(`doc/adr/`)约定, 但格式无关
- 记忆写入借鉴 **claude-mem/Mem0** 的自动捕获机制, 但加了 **B 确认制**
  解决"AI 总结是否可信"的问题; C 主动触发保证"你说算"
