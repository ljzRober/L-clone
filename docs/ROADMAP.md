# 路线图

> 回到 [README](../README.md)

## v0(已完成)

- 分层记忆(L0 流水 / L1 决策·记录 / L2 spec 索引)
- 回顾环(带记忆问答)与规范环(边界监督)
- **决策强确认**(B/C 统一: decision 一律待确认) + C 主动触发
- CLI + Web 面板(记忆工作台 + 问答) + REST API
- 竖向分层: 全局层 → 项目 → 模块 三级命名空间 + 格式无关 spec 索引
- **MCP server**(stdio + HTTP `/mcp`),Claude Code / Codex / DSH 插件接入
- **会话自动抽取**: hooks / 插件 → capture → 决策待确认 + note 逐轮聚合滚动压缩
- 记忆准入过滤 + 决策自筛(代码强制, 不依赖模型意图)
- 记忆链接 `[[m:N]]` + 召回跟随
- 上升/下降(promote/demote)+ 项目墓碑(rm/restore)
- 删除提示(suggest)+ 整理合并(organize)
- 接入向导(install)+ 自检(doctor)+ 在线备份(backup)+ web 服务化(serve)

## 设计取舍记录

| 决策 | 理由 |
|---|---|
| 记忆在服务器, 模型走 API | 数据可控 + 免 GPU 运维 + 永远用最新模型 |
| spec 权威留在项目仓库 | spec 是项目产物, 应随 git 版本化、可评审; 大脑只建索引 |
| 决策强确认(B/C 统一) | 决策是权威结论, 无论主动还是自动都"AI 写草稿、你盖章", 防幻觉 |
| 准入过滤代码强制 | "做了什么"归 git/spec, 记忆只留"定了什么规则/值得记的事实", 减少打扰 |
| 格式无关 spec 索引 | 不绑定 OpenSpec/ADR 等任何工具, 按路径模式启发式识别 |
| 模块作为次级竖向划分 | 项目内再分关注点, 分类加载按「项目→模块」分组, 减少噪声 |
