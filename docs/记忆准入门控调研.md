# 记忆/洞察准入门控调研：可直接借鉴的成熟方法

> 目的：回答"有没有成熟方法判断一条内容是否值得进长期记忆/是否算洞察"，并给出**能直接落到
> `lclone/gate.py` + 提炼提示词 + 待确认队列**的判据与阈值。
> 背景事故：`#761`（注入文本误触发旁路 + 模型自报「空」无哨兵）、`#768–771`（助手自己查出的
> 环境近况被当洞察推给用户）、`#772/#773`（通用设计常识被当洞察）。

## 0. 结论（TL;DR）

1. **有成熟方法，而且分成三个互不重叠的来源**，各有各的强项：
   - **A. LLM 智能体记忆系统的写入门控**（Mem0 / Zep / A-MEM / Memory-R1 / MemOS / Letta，以及
     ChatGPT、Claude 的产品级记忆策略）——最贴近我们的形态（对话文本 → 事实/洞察 → 存储），
     **抽取出什么样的东西**与**新旧记忆如何调和**都有公开提示词可抄。
   - **B. 认知科学与检索理论**（Generative Agents 的 poignancy 打分、MemoryBank 的遗忘曲线、
     ACT-R 的激活度、CBR 的 retain/案例库维护、新颖性/惊讶度）——提供**打分与生命周期**机制，
     而不是"收不收"的语义判据。
   - **C. 非 LLM 的知识管理标准**（KCS、ADR、事后复盘/NASA LLIS、ITIL KEDB、Zettelkasten、Diátaxis）
     ——几十年踩坑出来的**准入测试题**，多数可以逐字抄进提示词，且**与模型无关、可确定性执行**。
   - **D. "写入门控"专门研究线**（2026 新出现：WritePolicyBench、ConsistencyGate、MemGym）
     ——把"该不该写"本身当作可评测对象，有阈值、有基准、有量化证据；**这是与我们最贴的一档**。
2. **最该抄的四条**（一句话版）：
   - **"这是 decision 还是 fact？"**（ADR：只记录 architecturally significant 的**决定**；事实观察不在其列）
   - **"只从用户消息里取"**（Mem0 的抽取提示词原文如此，且明确写了惩罚条款；助手回声/元描述明确禁止）
   - **"写时支持度超过阈值才准入"**（ConsistencyGate：K 次采样求支持度分 + 阈值；我们已有的
     `has_user_evidence` 是它的便宜确定性版本，可构成两级门控）
   - **"延迟效用"而非"当下显著性"**（DAM：记忆的价值取决于未来交互，启发式只看相似度/新近度必然两头错）
3. **不要抄的**：Mem0 v3 / Zep main / MemOS / A-MEM 等主流系统现在**普遍转向"宁可多记"**（Mem0 v3
   原文："When in doubt, extract. A slightly redundant memory far less costly than a missing one."；
   Graphiti main："Extract liberally"）——因为它们的代价是检索精度，**我们的代价是你的复核时间**，
   所以我们的损失函数必须反过来设。其余不抄：知识图谱/时序图、RL 训练的记忆管理器、
   DAM 的值函数（论文无实验）。
4. **一个诚实的坏消息**：**没有任何同行评审、可独立复现的证据能证明某种写入策略能降低垃圾率**。
   现有数字要么不是关于写入策略的（厂商的检索/问答指标，且互相打架），要么是自报未复现。
   最好的一档是 A-MAC（F1 0.583）和 ConsistencyGate（污染 50%→34.1%，代价是召回 0.58）。
   → 所以**别指望抄一个"已验证的答案"**；能抄的是判据与机制，效果得**我们自己测**（见 §3）。
4. 我们**已经**有的（确定性闸门、用户轮证据、四段卡形状校验、空哨兵、去重、`recall_log`、
   `suggest`、人工确认队列）在同行里属于**偏严格且合理**的一档；缺的是三样：**显式重要度分数**、
   **复用/衰减驱动的生命周期**、**准入质量的度量**。

## 1. 我们的问题可以拆成四个独立判定

| 判定 | 问题 | 谁来判 | 现状 |
| --- | --- | --- | --- |
| J1 收不收 | 这段文本里有没有值得跨会话留下的东西 | 确定性闸门 + LLM 提炼 | 有（`gate.classify`），但只认信号词 |
| J2 抽什么 | 抽出来的是决策/教训，还是事实观察/回声/元描述 | LLM 提炼（提示词约束） | 弱：只写了"只收四类"，没有反例清单 |
| J3 值多少 | 它的未来效用有多大（要不要打扰人确认） | 需要显式分数 | **缺** |
| J4 留多久 | 何时该降级、失效、删除 | 生命周期策略 | 只有粗粒度 `suggest`（长期未召回） |

三个来源对 J1–J4 的覆盖并不相同：**C 类管 J1/J2（语义判据），B 类管 J3/J4（分数与生命周期），
A 类管 J2/J4（抽取与调和）**。

## A. LLM 智能体记忆系统的写入门控

### A1. Mem0（生产级，提示词公开）

来源：[mem0/configs/prompts.py](https://github.com/mem0ai/mem0/blob/main/mem0/configs/prompts.py)、论文 [arXiv:2504.19413](https://arxiv.org/abs/2504.19413)

**它把"只从用户消息抽取"写成了带惩罚的硬约束**（我们现在用 `has_user_evidence` 做的事，
它在提示词层就要求了）：

> `# [IMPORTANT]: GENERATE FACTS SOLELY BASED ON THE USER'S MESSAGES. DO NOT INCLUDE INFORMATION
> FROM ASSISTANT OR SYSTEM MESSAGES.`
> `# [IMPORTANT]: YOU WILL BE PENALIZED IF YOU INCLUDE INFORMATION FROM ASSISTANT OR SYSTEM MESSAGES.`

**完整性规则集（Integrity Rules）——几乎每一条都精确命中我们踩过的坑**：

| 规则 | 原文要点 | 我们的对应事故 |
| --- | --- | --- |
| No Fabrication | "Every detail must trace to the inputs. If you can't point to where it came from, don't include it." | 等价于我们"用户轮证据"的原则版 |
| No Echo Extraction | 助手复述/确认用户已提供的信息，**不得**再从助手消息里抽一遍 | `#761`：助手/子代理回声被当卡片 |
| No Meta-Extraction | 抽**内容**，不抽"用户要求缩短段落""用户分享了一份摘要"这类动作描述 | `#761` 的元报告形态 |
| No Within-Response Duplication | 同一次输出里语义重复只留信息更全的那条 | 我们只有跨轮去重 |
| No Detail Contamination | 不得把既有记忆的细节混进新抽取 | （我们暂无此问题，但会随链接功能出现） |
| 空结果契约 | `{"memory": []}`；few-shot 里 `Input: Hi. → Output: {"facts": []}` | 我们补的"空哨兵" |

**新旧调和（reconcile）四操作**：`ADD / UPDATE / DELETE / NONE`，逐条与新事实对比——
"信息更全者保留"、"矛盾则删除"、"已存在则 NONE"。可直接用于我们的 `suggest` 与去重升级。

**链接（linking）判据**：同实体/同话题、偏好更新、叙事延续、矛盾时才链接；
"Do NOT link memories that merely share a vague theme."——我们后续做 `[[m:N]]` 自动建链时可逐字照抄。

> ⚠️ **反向偏置（不要抄）**：Mem0 v3 提示词带一张 "Exhaustive Extraction Checklist"，写着
> "For conversations with 10+ messages, you should typically extract 5-15 memories. If you have
> fewer than 3, re-read the conversation"。它服务的是**个性化回忆（求全）**；我们要的是
> **求准 + 少打扰人**，抄它的完整性规则，别抄它的配额。

**更强的反向证据（OSS v3 已转向 ADD-only）**：迁移文档的章节名就是
"**Extraction: Single-Pass ADD-Only**"，即**不再做 UPDATE/DELETE 调和，新事实与旧事实并存**
（已核：[迁移文档](https://docs.mem0.ai/migration/oss-v2-to-v3) + [architecture.md](https://raw.githubusercontent.com/mem0ai/mem0/main/skills/mem0/references/architecture.md)）。
其官方立场是"宁滥勿缺"（此句据调研摘录，**我未逐字核**）：*"When in doubt, extract. A slightly
redundant memory far less costly than a missing one."*
→ 结论：**连头部厂商都把损失函数设在"宁可多记"那一侧**，因为他们的代价是检索精度，而我们的代价是
**你的复核时间**。我们的损失函数必须反过来设（重精确），这一点要在 spec 里写清楚，避免以后照搬厂商默认。
另注：Mem0 论文里的 ADD/UPDATE/DELETE/NOOP 调和**没有任何写入策略消融实验**，其论文数字全部是
检索/问答指标。

### A2. 专门研究"写入门控"的一条线（2026，最新且最贴题）

这条线研究的正是我们的问题（J1：**该不该写**），而不是泛泛的记忆系统。

**WritePolicyBench**（[arXiv:2602.02574](https://arxiv.org/abs/2602.02574)，2026-01）
定义"memory write policy"= 在**严格字节预算**下决定**存什么 / 合并什么 / 淘汰什么**的决策规则，
并给出可控非平稳（document/API drift）的任务生成器 + 显式动作接口 + 字节精确成本模型 +
同时衡量**任务成功率与预算效率**的标准指标。→ 对我们的价值：它把"写入策略"变成可评测对象；
我们缺的正是"收紧后到底有没有变好"的度量（见 §3）。它内置的 **drift** 概念也解释了我们
为什么不该记环境近况：这类事实会随环境漂移，写进去就是未来的错误前提。

**ConsistencyGate**（[arXiv:2607.22962](https://arxiv.org/abs/2607.22962)，2026-07）
**写时准入闸门**：在提交一条候选事实前，向 LLM 查询 K 次得到"软支持度"分数，**只有平均分超过
阈值才准入**；模型无关、无需微调，延迟敏感场景可退化为单次前向的对数概率版本。摘要里有两句
直接命中我们的现状：

> "existing memory management addresses retrieval and capacity but not **write-time correctness**;
> this admission problem **cannot be solved by utility- or recency-based criteria**"
> "reduces contamination ... with the cost concentrated on facts that are stated only implicitly
> in the source context"

→ 对我们的价值：这是"用户轮证据"的**升级版**——我们现在用确定性 bigram 重叠判"这条主张在用户轮里
有没有出处"，它用 K 次采样的支持度分 + 阈值判"这条主张是否被源上下文支持"。两者是**同一原理的
便宜版/严格版**，天然构成两级门控：便宜的确定性门先挡掉绝大多数，剩下的疑难再问 LLM 要支持度分。
它同时开源了三个 benchmark（LoCoMo-Contam / MSC-Contam / MemContam），若我们要量化"误记率"可以直接用。

**A-MAC — Adaptive Memory Admission Control**（[arXiv:2603.04549](https://arxiv.org/abs/2603.04549)，2026-03）
**目前唯一"显式打分 + 阈值"的准入门控，也是最可直接照搬的一个**。把记忆价值拆成五个可解释因子：
**future utility / factual confidence / semantic novelty / temporal recency / content type prior**，
用轻量规则抽特征 + **一次** LLM 效用评估，再通过交叉验证学一个域自适应策略；
准入判据就是 `S(m) = w·[U,C,N,R,T] ≥ θ`（论文最优 θ = 0.55）。摘要原文（已核）：

> "A-MAC achieves a superior precision-recall tradeoff, improving **F1 to 0.583** while reducing
> latency by **31%**... Ablation results identify **content type prior** as the most influential
> factor for reliable memory admission."

→ 对我们的价值：①它证明了"**显式、可解释的准入控制**"本身就是一个设计原则；②**"内容类型先验"是最强因子**
——这独立印证了 ADR 的"这是决定还是事实"和 Diátaxis 的"先分类再判价值"；③它的 θ 是**用标注数据
交叉验证**出来的，我们将来可以用自己的 keep/delete 记录（review 动作）标定自己的 θ。
④注意它的精度数字：precision 0.417 @ recall 0.972（一个基准、N=225、金标由 LLM 生成）——**别把 0.583 当成绝对水平**。
（该文常被二手来源误标为"RL 学习型写入门控"，实为网格搜索 + 5 折 CV，非 RL。）

**MemGym**（[arXiv:2605.20833](https://arxiv.org/abs/2605.20833)，2026-05）
**agentic** 记忆基准（不是聊天个性化），覆盖 tool-use 对话（tau2-bench）、多轮深度研究、
**编码（SWE-Gym / MEMGYM-CODEQA）**、computer use（WebArena-Infinity）四类场景，并且报告
**memory-isolated score**（把记忆能力与推理/检索/工具使用解耦），还训了个轻量奖励模型 MemRM
（Qwen3-1.7B + QLoRA）给压缩质量打快速标量分。

摘要里那句批评正是我们的处境：

> "Existing memory benchmarks predominantly evaluate retention of **personalized information in
> multi-turn chat** scenarios, overlooking the **dynamic memory formation** that occurs during
> extended agent execution. Consequently, the memory systems they produce **transfer poorly to
> realistic agentic environments, such as coding** and web navigation."

→ 对我们的价值：①它是唯一把**编码**场景纳入的记忆基准，和我们同域；②它提醒我们
**聊天型记忆的判据（Mem0 那套个性化偏好）不能照搬到编码智能体**——我们的"值得记"应以
"未来施工会不会用上"为准，而不是"像不像用户偏好"。

### A3. 其他系统与产品级策略（已核实部分）

**mem0 平台（v3）的真实写入策略**：**ADD-only** + MD5 哈希去重（拦精确重复），流水线里
**没有 UPDATE/DELETE**；`top_k=20`、`threshold=0.1`。注意：论文里描述的"四操作调和"是**论文**，
线上平台是 ADD-only（[architecture.md](https://raw.githubusercontent.com/mem0ai/mem0/main/skills/mem0/references/architecture.md)）。
→ 对我们的意义：**连厂商自己都没把 DELETE 放进自动流水线**，删除留给人和后台整理——
这正好支持我们"只提示、不自动删"的纪律。

**Zep / Graphiti**（[arXiv:2501.13956](https://arxiv.org/abs/2501.13956)）：把事实写成**双时态
有效期区间**，过期是"**失效（invalidate）**"而不是"擦除"，并保留 supersedes 链。→ 直接可抄的
是**"标失效 > 删除"**这条纪律（我们目前 `suggest` 只提议删除）。

**LangMem**（[概念文档](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/)）：
把我们的两难讲得最清楚（原文）：

> "If the system **over-extracts**, this could lead to **reduced precision** of memories when your
> agent needs to search the store. If it **under-extracts**, this could lead to **low recall**."
> "memory relevance is more than just semantic similarity. Recall should combine similarity with
> **'importance'** of the memory, as well as the memory's **'strength'**, which is a function of how
> **recently/frequently it was used**."

还给了两个我们可直接借的结构：
- **Profile vs Collection**：Profile 是**单文档、就地更新**，适合"只关心最新状态、避免记多余信息"；
  Collection 才是无界知识卡。→ **#768–771 这类环境近况本来就该进 Profile（一份就地更新的档案/文档），
  而不是卡片流**。
- **Episode schema**（observation / thoughts / action / result）：比"要点/背景/影响"更适合**教训/复盘**
  类卡片，可直接作为我们"教训"卡的四段模板。

**GitHub Copilot Memory**（[VS Code 文档](https://raw.githubusercontent.com/microsoft/vscode-docs/87b837c9/docs/copilot/agents/memory.md)）：
产品级写入策略里有四条**可核实的硬措施**（原文）：
"**Repository-scoped** ... can only be created by contributors with write access"、
"**Verified before use**: agents validate memories against the current codebase before applying them,
preventing stale or incorrect information"、
"**Automatically expired**: memories are deleted after **28 days** to avoid outdated information"、
以及 `Repository Settings > Copilot > Memory` 里的人工 review/delete 面。
此外它的本地记忆工具把记忆分成 **user / repo / session** 三个作用域，**session 作用域在对话结束即清空**。
→ 对我们的意义：①**TTL** 是治"近况漂移"的直接办法；②**用前校验**（`verified before use`）比
写时判据更省事；③"会话级临时上下文不该进长期库"应当成为硬边界。

**Memory-R1**（[arXiv:2508.19828](https://arxiv.org/abs/2508.19828)）：用 RL 训一个记忆管理器，
动作空间 `ADD / UPDATE / DELETE / NOOP`，**奖励 = 施加该操作后下游问答的 exact match**。
→ 我们**不训 RL**，但可借两点：(i) 四操作分类；(ii) **反事实写入评估**——"这张卡存在/不存在，
答案会不同吗？"，这是"未来会不会被用上"的可操作代理。
（其分析也指出：DELETE 会销毁纠错历史。）

**Letta "sleep-time compute"**（[arXiv:2504.13171](https://arxiv.org/abs/2504.13171)）：把记忆整理
放到空闲期由第二个 agent 做（约 5× 测试算力下降、+13%/+18% 精度）。→ 概念可用（我们的
`suggest`/后台整理），但**没有写入精确度指标**，不要当证据。

**Letta / MemGPT**（sleep-time compute 的提示词，**已核仓库原文**）：核心是一句可以用作判据的自我约束——
*"**Not every observation warrants a memory edit**, be selective in your memory editing, but also aim
to have high recall"*；工具描述里还有两条硬要求：*"Store **self-contained** facts or summaries,
**not conversational fragments**"*，以及 *"do not write 'today' or 'recently'… because the memory is
persisted indefinitely"*（后者正是"近况不该入库"的另一种说法）。
→ **自包含性**这条可以直接变成我们的结构检查：**背景/影响两段若离开原始对话就填不出来，说明它不是一个
自包含的知识单元，应当拒绝**（比"四段标题存在"这个形状检查强得多）。

**Anthropic 官方 memory tool 的 Do/Don't**（[cookbook](https://platform.claude.com/cookbook/tool-use-memory-cookbook)）：
"Do: Store task-relevant patterns, **not conversation history**"；"Don't: ❌ Store sensitive
information (passwords, API keys, PII)；❌ **Let memory grow unbounded**；❌ **Store everything
indiscriminately**"。——官方文档级别的"不要什么都记"。

**OpenAI Agents SDK cookbook（最便宜的一条规则，可直接照抄）**：
*"Keep only **durable** information (preferences, stable constraints, memberships/IDs, long-lived habits)"*；
*"**Drop session-only / ephemeral notes**… e.g. contains phrases like **'this time', 'this trip',
'for this booking', 'right now', 'today'**"*；另要求去重、不得编造（"Do NOT invent new facts"），
并拒收 SSM/支付串与**指令形状的载荷**（instruction-shaped payloads）。
→ 这是一份**正则级的自动拒收清单 + 耐久类别白名单**，成本几乎为零，正好治我们的"环境近况"类。

**A-MEM**（[arXiv:2502.12110](https://arxiv.org/abs/2502.12110)）：**没有任何准入门槛**——每个交互块都存；
它的卖点是"memory evolution"（让 LLM 去 strengthen/update_neighbor）。⚠️ 但其实现是**就地覆盖邻居的
context 与 tags，没有审计轨迹**——对我们这种"记忆要能解释来源"的库是**反面教材**；消融显示收益主要来自
**链接**而非 evolution。

**Graphiti/Zep 当前 main 分支的自我反转**：早先的提示词写 "Only extract facts that… clearly stated
or unambiguously implied in the CURRENT MESSAGE"、"NEVER extract abstract concepts, feelings, or
generic words"，而现在的 main 变成 **"Extract liberally — when in doubt, extract the fact"**。
→ 又一家从"严"转向"宽"；这更加说明**我们必须按自己的损失函数（人工复核成本）单独设阈值**，
不能跟着厂商默认走。

**MemOS / SeCom / MemInsight（补充调研结论：都不能解决我们的问题）**：
- **MemOS**（[2505.22101](https://arxiv.org/abs/2505.22101) 是立场文、无实验；数字在 [2507.03724](https://arxiv.org/abs/2507.03724)）：
  只有**生命周期/淘汰**（TTL、访问频率 GC、LRU、优先级），**没有准入门槛**；实现是 write-all，
  去重只在单个 Cube 内。→ 无可借。
- **SeCom**（[2502.05589](https://arxiv.org/abs/2502.05589)，ICLR 2025）：唯一的滤波是**话题切换分段**，
  段内无论有没有价值都会存；它是压缩/检索的成果，**不是垃圾拒收的成果**。→ 只可借"按话题批量分组"。
- **MemInsight**（[2503.21760](https://arxiv.org/abs/2503.21760)，AWS）：**没有准入阈值**，每一轮都标注并保留原文；
  唯一可借的是一条**结构性微规则**：*"Don't include any unspecified or none values. If an attribute has
  a none or unspecified value skip this attribute."* → 映射到我们：**归属填不出来的卡应当被结构性拒绝，
  而不是送给人判断**（我们的 `归属` 段正好是这个属性的落点）。

（A-MEM / MemOS / SeCom / MemInsight 的写入策略已在上文逐条给出；结论：无一有准入门槛。）

## B. 认知科学与检索理论（J3 分数 / J4 生命周期）

### B1. Generative Agents（Park et al., 2023）——显式重要度打分

来源：论文 [arXiv:2304.03442](https://arxiv.org/abs/2304.03442)；官方提示词模板
[`poignancy_event_v1.txt`](https://raw.githubusercontent.com/joonspk-research/generative_agents/main/reverie/backend_server/persona/prompt_template/v3_ChatGPT/poignancy_event_v1.txt)
（**已抓原文**，措辞与上面一致，事件版用 "event" 而非 "piece of memory"）；官方代码
[`associative_memory.py`](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/memory_structures/associative_memory.py)
中每个 `ConceptNode` 带 `poignancy` 字段（**已核**）。

**调参经验（同一仓库/论文）**：论文给的人类校准锚点是 2 = "cleaning up the room"、8 = "asking your
crush out on a date"；**官方代码的兜底默认值是 4**（解析失败时用它）。→ 我们要用就**从阈值 4 起步**。

**另一个直接可借的机制（批量成卡触发器）**：Generative Agents 不是每轮都生成反思，而是当
**近期事件的重要度累计超过 150** 时才触发一次反思，再从中提炼 5 条高层洞察
（论文 §4.2：`Σ importance > 150`，提示词 "What 5 high-level insights can you infer…"）。
→ 映射到我们：**不是每轮都 mint 卡片，而是重要度攒够一次再批量提炼**——单这一条就能把
pending 队列的条数压下来，且完全确定性、不花额外 LLM 调用。

**每个记忆节点携带**：`poignancy`（重要度分）、`created` / `last_accessed`（时效）、`keywords`、
`kw_strength_event` / `kw_strength_thought`（关键词**使用计数**，即复用信号）、thought 的 `depth`
（由依赖链推出）。检索分 = 相关性 × 重要度 × 时效衰减。

⚠️ **论文与代码不一致（引用时要小心）**：论文写三个权重都为 1（各项 min-max 归一化），
时效衰减 0.995；而发布的代码里 `retrieve.py` 用 `gw = [0.5, 3, 2]`（相关 3 > 重要 2 > 时效 0.5）、
`scratch.py` 里 `recency_decay = 0.99`。另外 min-max 归一化是**语料相关**的，库一变大就不稳定——
我们若借用只借"重要度作为一维分数"这个思想，不抄归一化。


**重要度提示词（1–10，原文）**：

> "On the scale of 1 to 10, where 1 is purely mundane (e.g., brushing teeth, making bed) and
> 10 is extremely poignant (e.g., a break up, college acceptance), rate the likely poignancy of
> the following piece of memory."

**每个记忆节点携带**：`poignancy`（重要度分）、`created` / `last_accessed`（时效）、`keywords`、
`kw_strength_event` / `kw_strength_thought`（关键词**使用计数**，即复用信号）、thought 的 `depth`
（由依赖链推出）。检索分 = 相关性 × 重要度 × 时效衰减。

**可直接借鉴**：给每条洞察加一个**显式重要度分数**，并用它决定（a）是否入待确认队列、
（b）是否在 bootstr 里出现。把 `kw_strength` 的思路映射到我们的 `recall_log`：**被召回/被引用过
的洞察涨分，长期零召回的降分**——这正好补上 J4。

### B2. DAM / Beyond Heuristics（2025-12）——"延迟效用"框架

来源：[arXiv:2512.21567](https://arxiv.org/abs/2512.21567)

- 论点：记忆管理是**不确定性下的序贯决策**，记忆的效用是**延迟的**；纯启发式（相似度、新近度）
  会两头错——丢掉关键上下文，或积累噪声。
- 反直觉结论（作者原话）："memory operations with seemingly low immediate relevance can have
  high long-term utility, especially for user preferences and abandoned subgoals"。
- 作者自述"不是新算法，而是一次重构"：给出 value function / uncertainty estimator / aggregate
  policy 的框架，但没有公开阈值与基准分数。
- ⚠️ **立场提示**：该文在 [memorypapers.org](https://memorypapers.org/) 上的"TL;DR/图解"版本由
  **Mem0 官方运营**（站点页脚 "Built by Mem0"），属厂商相邻摘要，只能当索引、不能当一手证据；
  上面引用的框架结论均以 arXiv 摘要原文为准。

**对我们的意义**：#768–771 的问题不是"当下看着不重要"，而是**未来任何时刻都用不上**。
所以准入判据应当问"**未来谁会再用它一次**"，而不是"现在看起来重要不重要"。DAM 给了这个提问的
理论依据，但**不要**去实现它的值函数（需要环境与数据）。

### B3. 生命周期与去重的经典机制（cluster B 调研结果）

| 方法 | 精确判据/公式 | 来源 | 我们能实现吗 | 局限 |
| --- | --- | --- | --- | --- |
| **GA 反思触发（批量成卡）** | 近期事件**重要度累计 > 150** 才生成一次反思；先问"3 个最突出的高层问题"，再问"What 5 high-level insights can you infer…" | [论文 §4.2](https://arxiv.org/abs/2304.03442) | **能，且是最贴的机制** | 150 是仿真常数，要重标定 |
| **MemoryBank（艾宾浩斯）** | `R = e^(−t/S)`；S 初值 1，**每次被召回 S += 1、t := 0** | [论文 §2.3](https://arxiv.org/html/2305.10250v3) | **能**：三个确定性计数器 | 论文**没给删除阈值**，自述"exploratory and highly simplified" |
| **ACT-R 基础激活** | `B_i = ln(Σ_j t_j^(−d))`，d ≈ 0.5；`A_i = B_i + Σ W_j·S_ji + noise`；`A_i > τ`（默认 0.0）才可检索 | [ACT-R 教程 Unit 4](http://act-r.psy.cmu.edu/tutorials/unit4.pdf)（原 PDF 本次抓不到，公式经实现核对：[bodh](https://docs.rs/bodh/1.0.0/src/bodh/memory.rs.html)、[gactar](https://github.com/asmaloney/gactar/blob/v0.11.0/actr/modules/declarative_memory.go)） | **能**：只要存访问时间戳；B_i 完全确定性，τ 天然给出归档线 | 扩散权重/噪声需要我们没有的数据 |

| **CBR 的 Retain + 案例库维护** | 4R 循环的 Retain；Smyth & Keane 主张按**能力（coverage / reachability）**而非纯效用删除 | [Smyth & Keane 1995](https://mlanthology.org/ijcai/1995/smyth1995ijcai-remembering/) | 部分："coverage" ≈ "已有卡片覆盖了这条" | 需要适应/求解模型；本次只拿到摘要级信息 |
| **新颖性 / MMR** | 贝叶斯惊讶 = `KL(posterior‖prior)`；MMR = `argmax [λ·Sim1(d,q) − (1−λ)·max Sim2(d,d')]` | [Itti & Baldi 2009](https://doi.org/10.1016/j.visres.2008.09.007)、[MMR (Carbonell & Goldstein 1998)](https://dl.acm.org/doi/10.1145/290941.291025) | **MMR 能**（任何 LLM 调用之前的冗余门）；贝叶斯部分 | 文本上的贝叶斯惊讶会退化成 embedding 新颖度；DOI 未抓，属教科书级陈述 |
| **SM-2 / FSRS 间隔重复** | SM-2：`I(n)=I(n−1)·EF`，`EF' = EF + (0.1 − (5−q)(0.08 + (5−q)·0.02))`，EF 下限 1.3；FSRS-4.5：`R = (1 + FACTOR·t/S)^DECAY`，DECAY = −0.5，FACTOR = 19/81 | [Wozniak 1990](https://super-memory.com/english/ol/sm2.htm)、[FSRS wiki](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm) | **不能** | 需要每卡 0–5 的回忆评分；那是闪卡场景，编码会话里没有这种事件；且调度 ≠ 准入 |

**可直接借的四条**（按性价比）：

1. **重要度打分的官方提示词**（B1 已核实）直接作为铸造时的第五个字段，配一个**确定性阈值**
   （**从 4 起步**，等于官方代码的兜底值）。
2. **累计重要度触发批量成卡**（`Σ importance > 150`）：不每轮 mint，攒够再一次提炼——
   **单这一条就能压下队列条数**，且零额外 LLM 成本。
3. **MMR 式冗余门，放在任何 LLM 调用之前**：与已有/待确认卡的最大余弦相似度超阈值即丢，
   `λ` 调"相关性 vs 多样性"。我们已有向量去重，只需把它从"写入后"提到"调用前"。
4. **ACT-R 的基础激活 `B_i = ln(Σ t_j^−0.5)` + 归档阈值 τ**（要更简单就用 MemoryBank 的
   `R = e^(−t/S)`，召回即 `S += 1, t := 0`）：把"频率 + 新近度"合成一个有原则的分数，
   替换掉我们粗粒度的"长期未召回"。

**明确不借**：SM-2/FSRS 调度（没有可信的回忆评分，参数编码的是闪卡行为）、贝叶斯惊讶机器
（文本上退化为 embedding 新颖度）、CBR 的能力计算（需要适应模型，只保留"不要删掉某个区域的
唯一覆盖"这条直觉）、SOAR 的 chunking/epmem 触发（全记不忘，与目标相反）。

## C. 非 LLM 的知识管理标准（J1/J2 准入测试题）

### C1. ADR（Michael Nygard, 2011）——"重大决定"测试

来源：[Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions)

准入原文（逐字）：

> "We will keep a collection of records for **'architecturally significant' decisions: those that
> affect the structure, non-functional characteristics, dependencies, interfaces, or construction
> techniques**."

以及单条记录的边界：

> "One ADR describes **one significant decision** for a specific project. It should be something
> that **has an effect on how the rest of the project will run**."

记录结构 = **Context / Decision / Status / Consequences**（与我们的四段卡同构：要点≈Decision、
背景≈Context、影响≈Consequences、归属≈项目作用域）；决定被反转时的处理是**保留旧记录并标记
`superseded`**，而不是删除——这正是我们 `suggest` 删除策略缺的那一环（**标失效 > 删除**）。

**关键判据**：一条记录必须是**决定**（有 forces、有 response），**不是一条事实观察**。
按这条，#768–771（"skill 装在哪""dshmarket 管什么"）是事实观察，**根本不该成卡**——
这比我们现在的"环境近况"负信号更本质。

2. **Zettelkasten 的"拿不准就先写下来"**：单人自读工具没有人工确认队列，照搬就是复现我们的 bug。
3. **ITIL KEDB**：要求已诊断的根因 + 绕行方案，只能裁决事后错误知识。

**一条被数据打脸的理想主义**（值得警惕）：NASA 的判据很严，但 GAO 的问卷显示教训**几乎没人用**
（17.5% 应用过、43% 两年内一条都没提交、53% 认为有用率 <25%）。
→ 结论：**准入门槛再漂亮，也救不了"没人需要它"**；这条反向支持我们把"未来会不会被用上"
（复用率/反事实写入）当作核心判据，而不是把格式写得更好看。

## 2. 建议：v0 准入评分卡（可直接进提炼提示词）

**总纲**（NASA LLIS 的措辞最完整，直接抄）：
> 一条内容要成卡，必须 **significant**（对实际工作有真实或假定的影响）、**valid**（事实与技术正确）、
> **applicable**（指向某个具体的设计/流程/决定，能减少重犯或强化好结果）。

在此之上，加**五个必答问**（任一为否即不收）：

1. **它是决定，还是事实观察？**（ADR）——事实观察只有在"以后会被反复引用、且重获成本高"时才收。
2. **是谁说的？**（Mem0）——只从用户消息取；助手单方面结论不收（用户显式说"记一下"才豁免）。
3. **未来谁会在什么场景下再用它一次？**（KCS reuse 判据 + DAM 延迟效用）——答不上来就不收。
4. **重获它的成本 vs 记住它的成本？**（可重测性）——一次 `ls` / `git status` / `docker inspect`
   能拿到的近况一律不收。
5. **如果它被记错，会不会导致错误决策？**（不可逆性）——会 → 必须人工确认；不会 → 至多进摘要区。

再叠加一个**重要度分数**（Generative Agents 的 1–10，阈值管"要不要打扰人"而不是"收不收"），
以及一份**反例清单**（不收：环境近况 / 通用常识 / 进度汇报 / 助手回声 / 元描述）。

三条**结构性**建议（不是判据，是容器选择）：

1. **近况类信息进"档案"，不进"卡片流"**（LangMem Profile vs Collection）。环境/路径/开关当前值
   应当落在**一份就地更新的文档**（repo profile、`CLAUDE.md`、`docs/` 之类），而不是各自成卡——
   这样既不会污染卡片流，也能被"用前校验"。
2. **加 TTL + 用前校验**（Copilot Memory：28 天自动过期 + "verified before use"）。
   与其在写入时纠结"这条会不会过期"，不如**允许记、但设过期与使用前校验**——这比准入判据便宜。
3. **标失效 > 删除**（Zep 双时态 + ADR 的 `superseded`）。矛盾/过时的记忆应当被标记为失效并保留
   源流，而不是消失；删除留给用户显式动作（我们已有这条纪律，值得写进 spec）。
4. **晋升只依据观测到的复用**（KCS："reuse is review"；"Do not review articles for the sake of
   review"）。卡片从 pending → active → 长期保留，依据的是**被召回命中的事实**（我们有
   `recall_log`），**不是** LLM 的置信度。同一原理反用：长期零召回的卡自动进入整理候选。
5. **先分类，再判价值**（Diátaxis：action or cognition? acquisition or application?）。
   决策 → 卡片/ADR；步骤 → how-to/脚本；事实近况 → 档案（单文档）；三者都不是 → 直接丢。
   分类是便宜且确定性的，能先砍掉一大半噪声，剩下的才值得花 LLM 判据。

## 3. 度量与基准：怎么证明收紧有效

### 3.1 坏消息：主流基准**不评写入质量**

调研结论（cluster D）：**没有任何主流 agent-memory 基准给"写入精确度/垃圾率/存下来的东西有没有用"
打分**。它们全都测"检索/回答准确率"，而库是由某个写入策略预先建好的——写入质量被当成常量。
到目前为止与"写入"沾边的信号只有五个：MemoryAgentBench 的 Conflict Resolution 轨道、
MemGym 的 MemRM（压缩质量奖励模型）、Memory-R1 的反事实操作奖励、记忆投毒论文的注入成功率、
以及厂商自己公开的写入策略。

| 基准/指标 | 测什么 | 来源 | 我们能用吗 |
| --- | --- | --- | --- |
| LongMemEval | 500 题 QA 准确率；含知识更新、abstention。只优化读侧 | [arXiv:2410.10813](https://arxiv.org/abs/2410.10813) | 部分：借"知识更新/该弃答"的题型做手写回归 |
| LoCoMo | QA + 摘要 + 多模态生成（~300 轮/35 会话） | [arXiv:2402.17753](https://arxiv.org/abs/2402.17753) | 否：规模与判分成本不匹配 |
| MemoryAgentBench | 四项能力；**Conflict Resolution**（矛盾能否被正确解决）最接近写入质量 | [arXiv:2507.05257](https://arxiv.org/abs/2507.05257) | **可借**：手搓 ~20 组矛盾事实对，检查最终库状态 |
| MemGym | 含编码场景的 memory-isolated score；MemRM 评压缩质量 | [arXiv:2605.20833](https://arxiv.org/abs/2605.20833) | 否：需要 gym/Docker |
| Memory-R1 | 四操作策略；奖励=操作后问答 exact match | [arXiv:2508.19828](https://arxiv.org/abs/2508.19828) | 部分：借四操作+反事实写入评估 |
| MINJA（投毒） | 仅通过对话即可注入记忆：注入成功率 >95% | [arXiv:2503.03704](https://arxiv.org/abs/2503.03704) | **可借且便宜**：把对抗/指令形状的文本灌进提炼器，数有几条被存成事实 |

### 3.2 好消息：四个指标我们现在就能算（SQLite 即可）

| 指标 | 定义 | 目标 | 数据来源 |
| --- | --- | --- | --- |
| **队列精确率** | `keep / (keep + delete)`（窗口内已被处理的卡） | ≥ 0.5；< 0.3 说明人开始无脑点 | `memories.status` + review 动作 |
| **复核负担** | 每会话新增 pending 卡数 | ≤ 5 | `memories.created_at` + `session_key` |
| **垃圾率** | 已入库卡中"在其来源轮里找不到近似逐字支持"的比例 | 越低越好 | 卡片 ↔ 来源会话文本；脚本算（词重叠/余弦） |
| **复用率** | 被 `recall` 命中过的 active 卡占比（+首次命中时延中位数） | 越高越好 | `recall_log` |
| （免费第五个）去重率 | 插入时已有近似重复的比例 | 越低越好 | 插入时的判重结果 |

**为什么"队列精确率"是核心指标**：告警疲劳的系统综述里，误报率高的告警被人**忽略/绕过 49–96%**，
而"信号噪声比差"被点名为根因（[AHRQ 摘要](https://digital.ahrq.gov/health-it-tools-and-resources/health-it-costs-and-benefits-database/overriding-drug-safety-alerts)引 van der Sijs 2006 系统综述）。
一个低精度的 pending 队列会**摧毁它所依赖的人工信号**——这正是你上周的感受，现在有文献支撑。

⚠️ **诚实的前提**：这四个指标都是**内部相对指标**，只在"准入改动前后对比"时有效，不能横向宣称绝对质量
（因为没有公开的写入精确度基准可比）。

### 3.3 一个不该照抄的做法（待验证假设）

有分析认为"**新近度/ TTL 衰减把'最近没用'和'已经失效'混为一谈**"，因而基于结果的效用排序更优。
该说法来自单一来源、**未经独立验证**，只当假设看；不过 LangMem 的设计（召回分 = 相似度 + 重要度 +
strength）与它方向一致。

### 3.4 写入策略到底有没有"降垃圾"的实证？没有

这是本次调研最该记住的一条结论：**没有任何同行评审、可独立复现的结果证明某种写入策略能降低垃圾率。**
现有数字按"与降垃圾的相关度"排序如下：

| 结果 | 数字 | 关键警告 |
| --- | --- | --- |
| **A-MAC** | F1 **0.583**（对比 A-Mem 0.541 / MemoryBank 0.452 / MemGPT 0.324）；precision 0.417 @ recall 0.972 | 单基准、N=225、**金标由 LLM 生成**；作者自述是"结构化决策问题"的初步验证 |
| **ConsistencyGate** | 污染率 50%→**34.1%**（LoCoMo-Contam）、50%→**1.2%**（MemContam）；但**召回只有 0.58**，干净数据上 F1 0.267 vs 直接全写 0.271（略差） | 会**过度拒收"只在上下文里隐含"的事实**；干净场景没有收益 |
| **WritePolicyBench** | 阈值策略 F1 **1.000** vs 全写 0.155 | 合成数据、**相关性标签由生成器给出**、单作者、未同行评审 |
| **FGHM**（付费墙） | 污染 38%→9% | 作者自报、无预印本/代码、**未验证** |
| **Memory-R1** | 比 MemoryOS +28.5% F1 | 测的是**答案质量不是垃圾率**；官方仓库是 stub（"Code coming soon"），**不可复现** |
| **Mem0 / Zep / A-MEM** | 各种 LoCoMo/QA 数字 | **没有写入策略消融实验**；且互相指责：Zep 原称 84% 后承认 75.14%，反驳 Mem0 的文章由 Mem0 的 CTO 署名，另有报告称纯文件系统就打赢 Mem0（74.0 vs 68.5）——**没有一方经同行复现** |

→ 对我们的实际含义：**别指望抄一个"已验证的答案"**。我们能抄的是**判据与机制**（§2、A/B/C 三节），
效果必须用**我们自己的 keep/delete 数据**测（§3.2 的四个指标）；而 A-MAC 的 θ=0.55 也应当用我们的
review 记录来标定，而不是直接照搬。

## 4. 不借鉴清单（避免过度工程）

- **把聊天型记忆的判据照搬过来**：MemGym 摘要明确指出，现有基准"predominantly evaluate retention of
  **personalized information in multi-turn chat**"，导致其产出的记忆系统"transfer poorly to realistic
  agentic environments, such as **coding**"。我们的"值得记"应以"未来施工会不会用上"为准，
  而不是"像不像用户偏好"（[arXiv:2605.20833](https://arxiv.org/abs/2605.20833)）。
- **Zep/Graphiti 式时序知识图谱**：需要实体/关系抽取 + 图库，收益在我们的规模（单机、单人、
  几百条卡）不成立；只借"标失效不删除"这一条。
- **Memory-R1 式 RL 训练的记忆管理器**：需要奖励信号与训练环境，我们没有。
- **DAM 的值函数/不确定性估计**：论文自己说不是算法；落地需要环境建模。
- **embedding 惊讶度/新颖性**：我们的 `BRAIN_EMBED_BACKEND=local` 是哈希向量，语义惊讶度不可靠。
- **Mem0 v3 的穷尽式抽取配额**：与我们"求准、少打扰"的目标相反（见 A1 警告）。
- **间隔重复（SM-2/FSRS）用于知识卡**：它是为"记忆提取练习"设计的，对"知识库召回"没有直接对应。
- **把 TTL/新近度当作主要相关性信号**：见 §3.3 的未验证提醒——它会把"最近没用"误判成"已经失效"。
- **完整跑 LongMemEval / LoCoMo / MemGym**：它们测读侧准确率、需要数据集与 LLM 判官或 Docker；
  我们只借它们的**题形与指标定义**。

## 5. 差距分析：我们已有什么、缺什么、按 ROI 排序做什么

**已经对齐同行（甚至更严）的部分**：

| 我们已有 | 对应成熟做法 |
| --- | --- |
| 确定性闸门 `gate.classify`（skip/candidate/uncertain，0 次 LLM 调用） | KCS 的"脚本优先"、LangMem 的 hot-path vs background 分流 |
| 用户轮证据 `has_user_evidence` | Mem0 提示词的 "SOLELY BASED ON THE USER'S MESSAGES"；ConsistencyGate 的便宜确定性版 |
| 空哨兵 + 四段形状校验（本次新加） | Mem0 的空结果契约 `{"memory": []}` |
| 向量去重 + 归一化文本去重 | mem0 平台的 MD5 去重（我们更强） |
| `recall_log` + `suggest` | KCS 的复用遥测雏形（**原料已有，但没接进准入**） |
| 人工确认队列 + 只提示不自动删 | KCS 的 Not Validated 状态、Copilot Memory 的人工 review 面 |
| promote/demote（项目↔全局） | LangMem 的 namespace 分层 |

**第 0 步（几乎零成本，先做）**：

- **耐久性白名单 + 短时性黑名单**（OpenAI cookbook）：正则级拒收含"这次/今天/for now/`today`/
  `right now`"之类短时标记的内容；只放行"偏好、稳定约束、标识符、长期习惯"这类耐久信息。
  这一条基本就能把"环境近况"挡在门外，且不花 LLM 调用。
- **自包含性检查**（Letta）：**背景/为什么、影响/以后注意两段若离开原始对话就填不出来 → 直接拒收**。
  这比现在的"四段标题存在"形状检查强得多。
- **归属为空即拒**（MemInsight 的字段级规则）：`归属` 填不出来的卡应**结构性拒绝**，不送人判断。

**三个真正的缺口（按 ROI 排序）**：

1. **没有显式可解释的准入打分**（A-MAC + B 类）——不要只加一个"重要度"，而是照 A-MAC 的五个因子
   `[future utility, factual confidence, semantic novelty, temporal recency, content type prior]`
   打一个 0–1 的分，**阈值 θ 用我们自己的 keep/delete 记录标定**（而不是照搬 θ=0.55）。
   其中"内容类型先验"被 A-MAC 的消融证明是**最强因子**，正好复用我们已有的四段卡分类
   （决定/约定/规则/教训 vs 事实/近况）。配套两条零成本机制：①**累计重要度触发批量成卡**
   （Σ > 150，不每轮 mint）；②**MMR 式冗余门提到 LLM 调用之前**。
2. **没有复用驱动的生命周期**（KCS + LangMem 的 strength）——把 `recall_log` 接回来：
   用 **ACT-R 的 `B_i = ln(Σ t_j^−0.5)`**（或更简单的 MemoryBank `R = e^(−t/S)`，召回即
   `S += 1, t := 0`）把"频率 + 新近度"合成一个分数；被召回 ≥N 次 → 自动 active / 长期保留；
   低于归档阈值 τ → 进整理候选；矛盾/过时 → **标失效不删除**。
   这条能把"留多久"（J4）从"靠人记着"变成"靠事实说话"。
3. **没有写入质量度量**（D 类）——先只上 §3.2 的两个：**队列精确率**与**每会话复核负担**。
   没有基线，任何准入改动都是凭感觉；有了这两个数，收紧/放宽才有依据。

**现在不该做的**：把**单一的**"重要度/显著性"分数直接当准入门槛——DAM 的警告正是"当下看似不重要的
内容可能有高长期效用"，会误杀；要设分数门槛就必须像 A-MAC 那样把 **future utility** 与
confidence/novelty/type prior **一起**计入、并用数据标定。此外：不要把 TTL/新近度当主要相关性信号
（§3.3）；不要上图谱/RL；ConsistencyGate 的 K 次采样门控值得关注，但它会**过度拒收隐含事实
（召回 0.58）**且干净数据上无收益，等"误记"真的成为问题时再上。

**如果只做一件事**：先上度量（缺口 3），再动判据——否则我们无法判断下一次收紧是变好了还是只是变少了。
