# 会话归属与落库约定

## 归属

- 项目身份是**归一化 git remote**：`git -C <cwd> remote get-url origin` → `host/group/repo`（去协议与凭据、去尾 `.git`、host 小写、**path 保留大小写**）。同一仓库换机器、换 clone 目录都收敛到同一个项目。
- 匹配顺序：**remote 精确 → 本地路径兜底（仓库根最长前缀）→ 自动注册**。本地路径只是「最近一次看到的位置」（单列、后写覆盖），不是身份。
- 自动注册：项目名 = 仓库 basename（撞名加 `-2` 后缀），`path` 与 `remote` 一并落库；命中一个 `remote` 为空的历史项目时会**惰性回填**，不新建项目。
- 后端单独部署时，**客户端必须把解析出的 `remote` / `project_id` 随请求上报**（capture / bootstrap / evolution_add）。服务端看不到客户端路径，跑 git 检测必然失败，不得据此降级为全局层。
- 经 MCP / CLI 写入时显式传 `project`（按 `lclone proj list` 的 `remote`/`path` 认项目名或 id），或传 `repo_remote=<origin>` 让服务端归一化匹配；确实不在任何项目内才用 `project=global`。
- 同一 remote 下出现多个项目 = 历史重复（换机器 / 换目录时按路径注册出来的）。用 `lclone proj dupes` 只读探测，确认后用 `lclone proj merge --src <旧id> --dst <保留id>` 合并（带可回滚备份，`proj rollback --backup <文件>` 还原）。
- fork 的 remote 不同 → 视为不同项目（刻意如此：不把不同仓库合到一起）。

## 落库

- 自动捕获 → `status=pending`（草稿，待确认）；用户显式确认、主动 `remember --confirmed`、以及首次种子内容 → `status=active`。
- 全局层（`project_id IS NULL`）永远加载；项目记忆只在项目活着时加载（项目被 rm 后靠墓碑不再加载）。
- 待确认条目若**已在全局层**，确认弹窗不会显示「提升至全局」——因为提升是空操作，不是被限制。

## 排错

「记忆没归到项目」按顺序查三件事：

1. 插件/客户端版本是否含客户端归属解析（旧版只发 `cwd`，远端后端下必然掉全局）；
2. 会话 cwd 是否在 git 仓库内、是否有 remote（都没有且未传 `repo_remote` → 无归属 → 全局层）；
3. 项目是否已注册（`lclone proj list` 看 `remote`/`path`），以及是否已经建成了重复项目（`lclone proj dupes`）。
