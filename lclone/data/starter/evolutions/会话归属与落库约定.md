# 会话归属与落库约定

## 归属

- 自动捕获的归属由**会话所在机器**解析：`git rev-parse --show-toplevel` → 匹配已注册项目的 `path`（最长前缀）→ 未注册则自动注册（项目名 = 仓库 basename）。
- 后端单独部署时，**客户端必须把解析出的 `project_id` 随 capture 上报**。服务端看不到客户端路径，跑 git 检测必然失败，不得据此降级为全局层。
- 经 MCP / CLI 写入时显式传 `project`（按 `lclone proj list` 的 path 最长前缀匹配）；确实不在任何项目内才用 `project=global`。

## 落库

- 自动捕获 → `status=pending`（草稿，待确认）；用户显式确认、主动 `remember --confirmed`、以及首次种子内容 → `status=active`。
- 全局层（`project_id IS NULL`）永远加载；项目记忆只在项目活着时加载（项目被 rm 后靠墓碑不再加载）。
- 待确认条目若**已在全局层**，确认弹窗不会显示「提升至全局」——因为提升是空操作，不是被限制。

## 排错

「记忆没归到项目」按顺序查三件事：

1. 插件版本是否含客户端归属解析（旧版只发 `cwd`，远端后端下必然掉全局）；
2. 会话 cwd 是否在 git 仓库内（不在仓库内 → 无归属 → 全局层）；
3. 项目是否已注册（`lclone proj list`）。
