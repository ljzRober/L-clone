# 洞察格式模型（insight 三段分行）

每条 insight 按下述结构分行写，自包含、可独立读懂（共 2-4 句）：

```
要点：<一句话结论/规则>。
背景/为什么：<为什么这么定/背景/推理>。
影响/以后注意：<带来什么/以后注意什么>。
```

## 规则
- **一条 insight = 一件内容**（决定/教训/经验/观察），自包含；不要流水账，也不要压成一行干结论。
- 描述「做了什么」（改动/实现/上线/修 bug/重构）一律归 git/spec，**不写 insight**。
- 太长拆成多条。
- **引用就地写**：若这条 insight 指向某个进化资产 / 契约 / 源文件，就在**提到它的那句话里**写
  `[[evo:文件名.ext]]` / `[[spec:标识]]` / `[[src:路径]]`（link, not copy，权威内容留在原处）。
  **不要**在末尾单独起一行做引用列表——同一资产被写两遍就会渲染出两个一模一样的引用芯片。
- **不再有「归属」段**：卡片属于哪个项目由数据库的 `project_id` 表达，指向权威源由上面的就地表引用表达。
  在卡片正文里再写一遍「属于谁」既是重复，也无从校验（写个「无」永远能过）。
