# 洞察格式模型（insight 四段分行）

每条 insight 按下述结构分行写，自包含、可独立读懂（共 2-4 句）：

```
要点：<一句话结论/规则>。
背景/为什么：<为什么这么定/背景/推理>。
影响/以后注意：<带来什么/以后注意什么>。
归属：<项目级写 src:xx 或 m:NN；全局写 无>。
```

## 规则
- **一条 insight = 一件内容**（决定/教训/经验/观察），自包含；不要流水账，也不要压成一行干结论。
- 描述「做了什么」（改动/实现/上线/修 bug/重构）一律归 git/spec，**不写 insight**。
- 太长拆成多条。
- **指向进化资产**：若这条 insight 支撑某个进化文件（`~/.lclone/evolutions/`），在归属后写 `[[evo:文件名.ext]]`，例如 `[[evo:build-spec-map.sh]]`。
