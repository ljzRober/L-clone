## 洞察格式约定
要点：每条洞察按「要点 / 背景/为什么 / 影响/以后注意 / 归属」四段分行写，自包含、能独立读懂。
背景/为什么：格式规则只有放在全局层才处处可见——新增或重写记忆时才会遵循同一模板，不会随会话或实现漂移；让生成格式直接等于存储格式，省掉二次整理。
影响/以后注意：要改格式时先改这份约定，再同步提炼提示词；具体模板见 [[evo:洞察格式模型.md]]。
归属：无

## 记忆与-spec-分工
要点：能改写成「WHEN…THEN…」的契约归 spec（openspec），无法写成契约的理由/权衡/经验才进 lclone 记忆。
背景/为什么：代码改动与接口变化有 git 记录，需求与边界有 spec 承载；记忆区只留跨会话仍有用、又落不成契约的知识，避免同一件事两处存、两处漂。
影响/以后注意：一条内容半契约半理由时要拆开——理由进记忆、契约进 spec；洞察升格为硬边界时在记忆里写 [[spec:id]] 引用，不要双份维护。
归属：无

## 归属判定
要点：自动捕获的归属由会话所在机器解析；远端后端下必须显式带上解析结果，不得静默落进全局层。
背景/为什么：后端单独部署在服务器时，服务端看不到客户端路径，跑 git 检测必然失败；早期插件因此把大量项目洞察降级进全局层——表现就是待确认条目没有「提升至全局」勾选框（因为它已经是全局了）。
影响/以后注意：排查「记忆没归到项目」时，先确认插件版本是否含客户端归属解析，再确认会话 cwd 在 git 仓库内；细节见 [[evo:会话归属与落库约定.md]]。
归属：无

## 删除纪律
要点：记忆只提示、不自动删除——清理候选由 suggest 给出，删不删由用户明确决定。
背景/为什么：自动删除不可逆，误删的代价远大于留几条冗余；把判断权留在用户手里，工具只负责把「长期未确认 / 长期未召回 / 疑似重复」的信号摆出来。
影响/以后注意：定期跑 `lclone suggest` 看候选清单，而不是让任何流程自动清库。
归属：无
