## Why

洞察卡模板的第四段「归属」在实测数据里已经不再承载信息：线上 70 张 active 卡中 **36 张写「无」/「无。」、8 张缺该段、只有 26 张有实际内容**，而那 26 张写的基本都是指针（`src:ExceptionReportPage.tsx`、`src:sp-spec; src:lclone（m:451）`）——指针这件事现在已经有专门语法与数据表了（`[[evo:]]`、`[[spec:]]`、`[[m:N]]` + `memory_links`）。同时「归属非空」这条结构校验形同虚设：写个「无」就能过，从未真正拦下任何东西。第四段的另一半职能（项目归属）本来就由 `project_id` 列表达，卡里再写一遍是重复。

另一个现实问题是**引用被写了两遍**：本会话新造的两张指路卡 `#796`/`#797` 同时在「要点」里就地写了一次 `[[evo:…]]`、又在末尾按旧模板补了一次，导致看板弹窗并排显示两个一模一样的资产芯片、`recall` 也会把同一个资产重复带出两遍。与其禁止就地写，不如承认**就地写才是对的**：引用出现在它被提到的那句话里，比末尾挂一行孤立的指针更好读，也不会再出现重复。

顺带把全局层注入上限从 20 提到 100（用户要求；不加字符护栏，风险已知并接受）。

## What Changes

- **洞察卡改三段**：`要点 / 背景/为什么 / 影响/以后注意`，**去掉「归属」段**，也**不再有末尾引用行**；`[[evo:名字]]`/`[[spec:id]]`/`[[src:路径]]` 改为**就地写在正文里**（提到它的那句话中）。
- **结构校验同步**：`llm.CARD_SECTIONS` 去掉「归属」；「归属非空 → 结构性拒绝」这条规则**删除**（不再拒绝缺归属的卡）；自包含性规则不变（必须有「要点」且至少含「背景」或「影响」）。
- **提炼提示词同步**：四段 → 三段；新增一句「引用就地写在正文里，不要单独起一行做引用列表」。
- **链接助手改就地追加**：MCP `evolution_add --insight N` 关联既有卡时，不再在正文末尾新起一行，而是把 `（关联资产：[[evo:名字]]）` 追加进「影响/以后注意」段（缺该段则追加到最后一行）。
- **引用去重**（三处）：`evolutions_for_insight` 按资产名去重；`recall` 的进化资产边扩展按资产名去重（同一资产只带出一次）；看板记忆弹窗的 `[[evo:]]` 芯片按名字去重。
- **全局层注入上限 20 → 100**（`bootstrap(global_limit=100)`；`project_limit` 保持 20）。
- **数据订正**：`#796`/`#797` 去掉末尾重复引用行；`#655`（格式约定卡本身）改写为三段表述。
- **进化资产同步**：`洞察格式模型.md` 发 v4（三段 + 引用就地），`记忆准入标准.md` 更新「结构规则」段（删除归属非空硬规则）；仓库内 `lclone/data/starter/evolutions/*` 与 `starter/insights.md` 同步，保证种子与服务器一致。

## 方案

### 提示词与形状校验（`lclone/llm.py`、`lclone/memory.py`）

提示词里的卡片骨架改为三段，并补一句引用写法；`CARD_SECTIONS = ("要点", "背景", "影响")`（去掉「归属」）。原「归属非空」判断位于 `_filter_item` 之外（在 `llm.extract_memories` 的形状判定里，引用 `CARD_SECTIONS`/`CARD_REQUIRED`/`CARD_SUPPORTING`），改动集中在这两个文件，**闸门 `gate.py` 一行不动**（准入信号词表与本次无关）。

向后兼容：旧的四段卡**仍然可读、仍能召回**——过滤是"缺什么就拒"，不是"多了就拒"，所以带「归属」的存量卡不会被清掉，只是不再符合新模板。

### 引用就地化与去重（`lclone/memory.py`）

- `evolutions_for_insight`：对 `evo_refs()` 的结果按名字去重后再读内容（同一张卡重复提及同一资产时只返回一次）。
- `recall` 的进化边扩展：用 `seen_evo` 集合按 `name` 去重后再 append。
- `link_insight_to_evolution`：定位「影响/以后注意」所在行，把 `（关联资产：[[evo:x]]）` 追加到该行末尾；找不到该段就追加到最后一个非空行末尾。**不再新起一行**。

### 看板（`lclone/frontend/index.html`）

`openMem` 里解析 `[[evo:…]]` 时用 Set 按名字去重；沿用既有 `esc()` 与 `<button class="m-evo" data-evo>` + 事件委托（上一变更刚修完 XSS，不得回退成内联 handler）。

### 全局层上限（`lclone/memory.py`）

`bootstrap(..., global_limit: int = 100, project_limit: int = 20)`。该参数目前没有 CLI/API/MCP 覆盖入口，改默认值即全局生效。**已知并接受的代价**：注入体积随全局卡数量线性增长，当前 9 张卡 ≈ 3.1k 字符，按均摊 350 字符估算，100 张约 3.5 万字符（≈1.2 万 token）/会话首轮，且**没有字符护栏**。

### 数据与文档（不进代码）

`#796`/`#797` 去尾部重复行、`#655` 改写为三段；`洞察格式模型.md` v4、`记忆准入标准.md`、`starter/insights.md` 与 `starter/evolutions/*` 同步。

## Spec Constraints

- `memory-capture` > 记忆分类与确认：⚠️「准入 SHALL 先过确定性闸门（脚本优先，LLM 兜底）」与「闸门判定只在用户轮上做」等判定语义**不得改动**；本次只改**卡片形状**（段数与归属规则），`gate.py` 常量一字不动。
- `memory-capture` > 记忆分类与确认：⚠️ 自包含性（必须含「要点」且至少含「背景」或「影响」）与「归属填不出来 = 结构性拒绝」两条中，**只删后者**；前者必须保留。
- `memory-capture` > 闸门标准单一来源：⚠️ 准入标准仍集中 `gate.py`；卡片形状常量在 `llm.py`，两者不得互相复制词表。
- `memory-capture` > 进化资产与链接：⚠️「权威唯一在服务器版本化内容寻址库」「项目内脚本只记 ref 不入内容库」不变；引用写法变化**不得**引入任何新的发布或本地缓存写入。
- `evolution-store` > 版本化内容寻址存储 / 本地只读缓存与同步：⚠️ 改进化资产内容必须走 `publish`（append-only 新版本），**不得**原地改写 blob 或绕过版本库直接改本地缓存文件。
- `web-hierarchy` > 记忆工作台：⚠️ 新引入的可点元素必须键盘可达、动态内容必须经 `esc()`；转义审计（检查 303）不得放松，`_DYN_SINKS`/`_SAFE_INTERP` 只能按实测 RHS 同步。
- 全局层上限改动**不得**影响项目层上限（`project_limit=20` 不变），也不得改变「每会话只注入一次」的既有语义。
